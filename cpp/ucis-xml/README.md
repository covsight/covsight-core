# `ucis_xml.hpp` — schema-valid UCIS-XML coverage output, in one header

A tool that produces coverage — a simulator, an emulator, a testbench, a format
converter — copies **one header** into its tree and emits **schema-valid
UCIS-XML** by describing the coverage it collected, in the vocabulary it already
uses.

Nothing about XML, and nothing about the UCIS encoding, appears in caller code.

- **One file**: [`include/ucis_xml.hpp`](include/ucis_xml.hpp). Nothing to link.
- **No dependencies**: not zlib, not libxml, not even `<string>` if you set
  `UCIS_XML_NO_STL`.
- **C++17**, verified against Verilator 5.041's `-std=gnu++17` ceiling.
- **Dual-licensed `Apache-2.0 OR MIT`**, at your option. See [Licence](#licence).

```cpp
#include "ucis_xml.hpp"
namespace ux = ucisxml;

ux::CoverageWriter cov;
cov.openFile("coverage.xml");

cov.tool(ux::Tool().name("verilator").version("5.040").vendorId("VLTR"));
cov.test(ux::Test().name("run1").passed(true).seed("12345"));
cov.sources(design.sourceFiles());   // your compile file list; a superset is fine

for (const Module& m : design) {
    ux::Scope s = cov.scope(m.hierName, m.typeName);
    for (const Point& p : m.points) {
        switch (p.kind) {
        case Line:   s.line(p.file, p.line, p.count);                    break;
        case Toggle: s.toggle(p.signal, p.bit, ux::Edge::Rise, p.count); break;
        case Branch: s.branch(p.file, p.line).arm(p.arm, p.count);       break;
        }
    }
}

if (!cov.close()) fprintf(stderr, "%s\n", cov.error());
```

There is no `key`, no `inlineCount`, no `<options/>`, no `instanceId`, no `id`
element, no `metricMode`, no source-file id, and no schema ordering. The writer
supplies all of it.

## The whole contract

1. **Describe the tool, the test and the source files before emitting
   coverage.** The file list may be a superset, so it is the one you already
   have from compilation. (Callers that genuinely cannot enumerate files up
   front use `Sources::Deferred`.)
2. **Finish one scope before opening the next**, or nest them with
   `parent.child(...)`.
3. **Within a scope, emit anything in any order.**

Rule 3 is not a courtesy. Every scope is staged, sorted on its content, and
rendered when it closes, so the document depends only on *what* you emitted and
never on *when*. `tests/test_ux_order.cpp` builds the same document with the
containers and facts in five different orders and requires byte-identical
output.

## What it costs

Peak memory is bounded by the largest single scope, not by the design. Measured
on OpenTitan (1,241,667 points across 1,520 scopes): the largest scope is 37,404
points, about 4 MB staged; the median scope is about 25 KB. Reproduce with
`bench/coverage/scope_distribution.py`.

Errors never take a simulation down: there are no exceptions, no `abort`, and no
writes to `stderr`. The first error is latched, every later call becomes a no-op,
and `close()` reports. Building with `UCIS_XML_ASSERT(msg)` defined turns
contract violations into loud aborts instead, which is how the test suite is
built.

## Coverage kinds

Everything UCIS-XML can express: statement/line, block, process, branch (with
nesting), condition/expression (with nesting), toggle (with dimensions), FSM
states and transitions, assertions (all eight bins), covergroups, coverpoints
(range, sequence, illegal, ignore, default bins), and crosses. See
[`examples/`](examples) — one per kind, and `10_full_coverage.cpp` for all of
them at once. `tests/ucis_xml/test_schema.py` reads the complex types out of
`ucis.xsd` and fails if any of them has no fixture.

## Configuration

All `#ifndef`-guarded; set them on the command line or before including.

| Macro | Default | Effect |
| --- | --- | --- |
| `UCIS_XML_NAMESPACE` | `ucisxml` | Rename, e.g. when vendoring two versions |
| `UCIS_XML_ASSERT(msg)` | *(unset)* | Abort on a contract violation instead of latching |
| `UCIS_XML_NO_STL` | `0` | Drop the `std::string` conveniences and `<string>` |
| `UCIS_XML_NO_STDIO` | `0` | Drop `FILE*` sinks and the spool's temp-file spill |
| `UCIS_XML_NO_TIME` | `0` | Drop `<ctime>`; set `WriterOptions::writtenTime` yourself |
| `UCIS_XML_SANITIZE_UTF8` | `1` | Validate UTF-8 in caller strings |
| `UCIS_XML_BUFSZ` | 64 KiB | Output flush granularity |

## Building and testing

```
cmake -S cpp/ucis-xml -B build && cmake --build build && ctest --test-dir build
```

The directory configures standalone and has no dependencies, so you can build
and test it without the rest of covsight. `include/ucis_xml.hpp` is generated
from `src/` by `tools/amalgamate.py` and regenerated by the build; every test
runs twice, once against the split modules and once against the generated
header, so the artifact you would vendor is covered by the same suite.
